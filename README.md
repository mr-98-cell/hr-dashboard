# داشبورد متابعة إدارة استقطاب المواهب — مركز أداء

لوحة معلومات عربية (RTL) لمتابعة **التوظيف والتدريب والاستقالات والهيكل التنظيمي**،
بهوية مركز أداء، مع **إدخال وتعديل مباشر للبيانات** و**صلاحيات مستخدمين**.

---

## المحتويات

| الصفحة | ماذا تعرض |
|--------|-----------|
| **الرئيسية** | الملخّص التنفيذي: نسبة الإشغال بارزة · الشواغر · التحديثات · الإشغال حسب القطاع · التعيينات مقابل الاستقالات |
| **التوظيف** | نظرة عامة (الشواغر حسب القطاع + نسبة الإشغال + المخطط الشعاعي للهيكل) · المقابلات · مراحل التوظيف · الانضمام |
| **التدريب** | التحديثات · توزيع المتدربين · حالة الطلبات · جدول المتدربين بخمس مراحل |
| **طلبات تمهير** | التحديثات · توزيع المتدربين · حالة الطلبات · جدول الطلبات بخمس مراحل |
| **الاستقالات** | التوزيع حسب الدرجة والقطاع (مع أعلى وأقل قطاع) · جدول الاستقالات بمرحلتين |

> صفحة «القطاعات» لم تعد مستقلة — دُمجت في تبويب «نظرة عامة» داخل التوظيف.

### المزايا
- **الوظيفة سجل مركزي**: تُضاف مرة بمعرّف (`JOB-2026-004`) وتتحرك في سبع مراحل من «شاغرة» إلى «الانضمام».
- **العدّادات محسوبة لا مكتوبة**: الشاغرة = الوظائف المفتوحة، والمشغولة = المعتمدة − الشاغرة، ونسبة الإشغال تتبعهما.
- **الاستقالة تفتح وظيفة بديلة** تلقائيًا في نفس الإدارة بنفس المسمى والدرجة، مربوطة بسجل الاستقالة.
- **جدول الانضمام يمتلئ وحده** ممن بلغت وظيفته المرحلة الأخيرة، ويقبل الإضافة اليدوية.
- **سجل التحديثات**: كل إضافة/تعديل/حذف تُسجَّل تلقائيًا، مع ملاحظات يدوية من زر «إضافة تحديث».
- **مخطط شعاعي للهيكل**: سعة القوس بحجم وظائف الوحدة وامتلاؤه بنسبة إشغالها، والضغط يتعمّق.
- **تقرير PDF** بمحتوى مختار: الكل · التوظيف · التدريب · تمهير · الاستقالات.
- **تعديل العناوين** من زر «تعديل العناوين» في أي صفحة، وتُحفظ في قاعدة البيانات.
- **فلاتر موحّدة**: القطاع/الإدارة · السنة · الشهر.
- **صلاحيات ثلاث**: `owner` · `editor` · `viewer`.
- تصميم متجاوب يعمل على الجوال والحاسب.

## التشغيل السريع (وضع تجريبي بدون قاعدة بيانات)

```bash
cd hr-dashboard
python3 -m http.server 8080
```
ثم افتح <http://localhost:8080> وأدخل اسمك ورمز الدخول.

ثلاث صلاحيات، لكل واحدة رمز: **مالك** (كل الصلاحيات + تعديل العناوين) ·
**مُدخِل بيانات** (إضافة وتعديل وحذف) · **عرض فقط**.

الرموز تُسلَّم منفصلة عن المستودع. المخزَّن في `assets/config.js` هو بصمة
`PBKDF2-SHA256` (600,000 دورة) وليس الرمز نفسه، فلا تظهر الرموز في مصدر الصفحة.
لتغييرها: افتح `tools/hash-code.html`، ولّد البصمة، وضعها في `ACCESS_CODE_HASHES`.

البيانات تُحفظ في متصفحك فقط (`localStorage`) — مناسب للتجربة والعرض.

> ⚠️ **قبل النشر:** الوضع المحلي حماية واجهة فقط — البيانات كلها في المتصفح
> ويقدر أي مستخدم يقرأها من أدوات المطوّر مهما كانت صلاحيته. لا تضع بيانات
> موظفين حقيقية على رابط عام قبل ربط Supabase (الصلاحيات هناك مطبَّقة على
> الخادم عبر RLS). التفاصيل في قسم «الأمان» في `دليل-التسليم.md`.

بعد أي تعديل على ملفات `assets/` أعد بناء النسخة المفردة:
```bash
node tools/build-standalone.js
```

## الربط بقاعدة البيانات (Supabase)

### ١) أنشئ المشروع والجداول
1. أنشئ مشروعًا مجانيًا على <https://supabase.com>.
2. افتح **SQL Editor → New query**، والصق محتوى [`supabase/schema.sql`](supabase/schema.sql) ثم شغّله.
   ينشئ الجداول، وسياسات الحماية (RLS)، والهيكل التنظيمي الابتدائي.

   الجداول العشرة: `org_units` الهيكل · `jobs` الوظائف بمراحلها ·
   `interviews` المقابلات · `onboarding` الانضمام اليدوي · `trainees` التدريب ·
   `tamheer` تمهير · `resignations` الاستقالات · `updates` سجل التحديثات ·
   `settings` المستهدفات والعناوين · `profiles` المستخدمون وصلاحياتهم.

   > `jobs` حلّ محل جدولَي «الشواغر» و«المرشحون» — الوظيفة نفسها تحمل اسم
   > مرشحها وتتحرك في المراحل، فلا ازدواج بين سجلين.

### ٢) اربط التطبيق
من **Project Settings → API** انسخ `Project URL` و `anon public key` وضعهما في
[`assets/config.js`](assets/config.js):

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://xxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi...",
  ...
};
```

> `anon key` مفتاح عام وآمن للواجهة — الحماية الفعلية عبر سياسات RLS في قاعدة البيانات.

### ٣) أنشئ المستخدمين وحدّد صلاحياتهم
1. **Authentication → Users → Add user** (بريد + كلمة مرور).
2. من **Table Editor → profiles** عدّل الصف الخاص بالمستخدم:
   - `full_name`: الاسم الظاهر في أعلى الشاشة.
   - `role`: `owner` لمالك الداشبورد، أو `editor` لمُدخِل البيانات، أو `viewer` للإدارة (عرض فقط).

بمجرد ضبط `config.js` تتحوّل شاشة الدخول تلقائيًا إلى **بريد + كلمة مرور**.

## النشر

أي استضافة ملفات ثابتة تكفي (لا يحتاج خادم):

- **GitHub Pages**: Settings → Pages → Branch، ثم افتح `/hr-dashboard/`.
- **Netlify / Vercel**: اسحب المجلد أو اربط المستودع.
- **داخليًا**: انسخ المجلد على أي خادم ويب (IIS / Nginx / Apache).

## بنية الملفات

```
hr-dashboard/
├── index.html            # هيكل التطبيق
├── standalone.html       # نسخة بملف واحد (مولّدة — لا تعدّلها يدويًا)
├── assets/
│   ├── base.css          # تصميم الهوية (أداء)
│   ├── app.css           # إضافات الواجهة والدخول والنماذج
│   ├── config.js         # إعدادات الاتصال ← عدّل هنا
│   ├── data.js           # طبقة البيانات (Supabase / محلي) + الصلاحيات
│   ├── app.js            # المنطق والرسوم والصفحات
│   └── adaa-logo.png     # شعار أداء
├── tools/
│   ├── hash-code.html    # توليد بصمة رمز دخول جديد
│   └── build-standalone.js  # إعادة بناء standalone.html
└── supabase/
    └── schema.sql        # الجداول + RLS + بيانات ابتدائية
```

> `standalone.html` نسخة مطابقة بملف واحد. بعد أي تعديل على `assets/` شغّل
> `node tools/build-standalone.js` حتى تبقى النسختان متطابقتين.

## ملاحظات

- الهيكل التنظيمي (٥٨ وحدة) وأرقامه **تجريبية للعرض** — عدّلها من تبويب «نظرة عامة» في التوظيف أو من قاعدة البيانات.
- مستهدف التدريب السنوي يُضبط من جدول `settings` (`training_target`)،
  ومستهدف تمهير من `tamheer_target` في الجدول نفسه.
- لتصفير البيانات التجريبية في المتصفح: نفّذ `DB.resetLocal()` من Console ثم حدّث الصفحة.
